# XDYou 如何获取西电课表 / 个人信息（只读调研报告）

> 调研对象：`/Users/yves/github/xdyou`（XDYou / Traintime PDA，Flutter 开源项目，本地快照）。
> 方式：仅静态阅读代码与文档，**未修改 xdyou 任何文件、未发起登录或网络请求**。
> 结论：XDWe 若要「结合课表与个人情况」，建议先做**方案 A（手动/JSON 导入 + 只读展示）**，中期争取官方 API；不建议后端模拟 CAS。

## 1. 鉴权（CAS / IDS）

- 登录入口：`https://ids.xidian.edu.cn/authserver/login?service=<业务地址>`；登录页隐藏字段提供 `lt` / `execution` / `pwdEncryptSalt`。
- 密码加密：AES-CBC，key = `pwdEncryptSalt`，iv 固定为 `xidianscriptsxdu`；验证码为**滑块**（非图形码），本地用 NCC 图像匹配自动求解，失败可手动拖拽。
- 二次认证：IDS 返回 `reAuthLoginView.do` 时触发，支持短信 / 企业微信；异地或新设备容易触发。
- Cookie：客户端持久化存储，IDS 与 ehall 共用同一 Cookie jar；进入成绩/课表等业务前通过 `appShow?appId=...` 建立业务会话。
- **没有实现 WebVPN**；客户端只通过一个校园公告页判断是否在校外。

## 2. 数据来源（全部为 JSON 表单 POST，无官方 API）

| 数据 | 本科生（ehall） | 研究生（yjspt） |
|---|---|---|
| 课表 | `jwapp/sys/wdkb/.../xskcb.do`，另有学期开始日、未排课、调课三个接口 | `gsapp/sys/wdkbapp/.../xspkjgcx.do` + 校历接口 |
| 成绩 | `cjcx/xscjcx.do`（pageSize=1000） | `wdcj/xscjcx.do` |
| 考试 | `studentWdksapApp/wdksap.do` + 未安排考试接口 | `wdksapp/wdksxxcx.do` |
| 个人信息 | **没有姓名/学院/专业模块**，只存学号、密码、是否研究生、当前学期码 | 同左 |

- HTML 解析只用于登录表单、CAS continue 表单、校园卡 openid；课表/成绩/考试均直接解析 JSON。
- 课表渲染需要：学期码、学期开始日、课程名/代码/班号、时间安排（星期、起止节、周次、教室、教师）、未排课与调课/停课/补课合并逻辑（该项目为此写了约 300 行合并代码）。

## 3. 网络层与存储

- Dio 单例 + cookie_jar；UA 伪装 Chrome + XDYou；ehall 请求带专用 Referer/Accept 头；连接超时 10s、读超时 30s；无 TLS pinning、无代理。
- **无 RSA / 无签名字段**（仅体育系统有 RSA + timestamp + sign）；无全局重试，失败时回退本地缓存。
- 本地存储：SharedPreferences **明文**存学号与密码；课表/成绩缓存为明文 JSON；退出登录时清理。
- 无遥测；只有版本检查与用户同意后的崩溃邮件。许可证 MPL-2.0（文件级 copyleft），图标/开屏图不可复用。

## 4. XDWe 可选择的导入方案

| 方案 | 工作量（估） | 稳定性 | 封号风险 | 合规风险 | 说明 |
|---|---|---|---|---|---|
| **A 手动/JSON 导入 + 录入界面** | 2–3 天 | 高 | 无 | 低 | 不依赖学校系统；可复用其课表 JSON 字段结构，由学生自己粘贴/录入 |
| B 浏览器登录后复制 Cookie 给后端 | 3–5 天 | 中 | 低–中 | 中 | 不存密码，但会话短、跨 ids/ehall 两域、需反复操作 |
| C 后端模拟 CAS 登录 | 2–4 周+ | 中低 | 中 | **高** | 滑块可移植，但 2FA 无法自动化、改版即挂、集中存密码风险最高 |
| D 官方 API（争取） | — | 最高 | 无 | 最低 | 目前无公开 API；该项目 `docs/data_structure.md` 已在推动面向服务端开发商的数据结构 |
| E 移植 xdyou 协议 | 高 | 中低 | 中 | 中高 | 本质是 C 的 Dart→Python 移植，且需处理 MPL 义务 |

## 5. 建议

- **短期：A 方案**。XDWe 新增「学习档案」：学生手动录入课表（或粘贴 JSON）、薄弱知识点、每天可用时间；不存密码、不碰学校系统。
- **中期：争取 D 方案**（学校/学院正式接口或数据授权）；在此之前不实现服务端代登录。
- **不建议**复制：校园卡支付码/流水、睿思论坛、电费、请假报修、考勤、宿舍水机/空调、体育、图书馆、校园网查询等（身份/金融/第三方系统，超出最小必要范围）。
- **最小数据范围**：学期码、学期开始日、课程时间安排（星期/节次/周次/教室/教师）、可选考试安排与成绩聚合；不保存密码与 Cookie。
- **风险**：未授权自动化、2FA、滑块改版、appId/路径硬编码、调课合并复杂度、MPL 义务、服务端集中多账号请求触发风控。

## 6. 与 XDWe「今日该补什么」功能的衔接

拿到课表与个人情况后，可由 Agent 生成「少量、具体、有材料入口」的今日任务：

1. 从学生自己的提问历史 + 薄弱知识点出发，结合课表（今天/明天有课、可支配时间）排序；
2. 只给 1–3 个任务，每个任务绑定本地知识库的具体章节/资料入口（复用现有 BM25 引用与章节卡）；
3. 任务粒度明确（例如「用 15 分钟复习哈希冲突的两种解法，做 1 道变式题」）；
4. 学生完成后可反馈掌握程度，作为下一次排序依据。

> 以上依赖「学习档案/课表」数据；在用户确认采用方案 A 之前，不实现导入功能。
